# A11y audit — Mitra mockups v1 (2026-06-05)

Source artifact: `Mitra Mockups (standalone).html` (Claude design canvas export, 1.6 MB, 13 screens).
Auditor: `naksha:accessibility-auditor` (static DOM analysis from extracted React/JSX bundle — no live browser).
Spec baseline: WCAG 2.2 AA + `docs/design/a11y.md` + `docs/design/tokens.md`.

**Verdict:** Fail. **🔴 13 blocking · 🟡 11 drifts · 🟢 6 nits.**

This file is a punch-list for the next design pass. Each row is one concrete change. When every 🔴 is closed, run the audit again before the mockups land in `docs/design/` as canonical.

---

## Cross-cutting (every screen)

| Sev | Area | Issue | Fix |
|---|---|---|---|
| 🔴 | Icon-only buttons | `<button class="iconbtn">` (back, history, settings, share, more, mic) have no `aria-label`. | Add per-button `aria-label="Back"`, `aria-label="Audit history"`, etc. |
| 🔴 | Inline SVGs | `Ic()` SVGs have no `aria-hidden` / `focusable="false"`. Decorative icons get announced; icon-only buttons rely on missing labels. | `<svg aria-hidden="true" focusable="false">` for every icon. |
| 🔴 | Focus styles | Zero `:focus-visible` rules. `.mitra button { cursor: default; }` actively hides clickability. | `.mitra button:focus-visible { outline: 2px solid var(--primary); outline-offset: 2px; border-radius: inherit; }` + change `cursor: default` → `cursor: pointer`. |
| 🔴 | Reduced motion | Spin ring + dot pulse + undo countdown animate without `prefers-reduced-motion` guard. | Wrap every `@keyframes` consumer in `@media (prefers-reduced-motion: no-preference)` and provide a static fallback for `reduce`. |
| 🔴 | Landmarks | Every screen uses `<div class="screen">`. No `<main>`, `<nav>`, `<header>`, `<section>`. | Phone → `<main aria-label="…">`. Appbar → `<header>`. Actionbar → `<footer role="group">`. |
| 🔴 | RTL | All padding/margin use physical axes (`padding-left`, `margin-right`, `left: 6/26px` for toggle thumb). | Replace with `padding-inline-start/end`, `inset-inline-start`. Flip toggle thumb under `[dir=rtl]`. |
| 🔴 | Toggles | Settings rows + Wi-Fi-only + Background toggle are `<span class="toggle">`. Not focusable, not announced. | `<button type="button" role="switch" aria-checked={on} aria-label={…}>`. Wrap in 48×48 hit area; keep 52×32 thumb as decoration. |

## Dark-mode semantic-color contrast (NEW USAGE RULE NEEDED)

The tokens-doc contrast table was computed for **`success`/`warning`/`info`/`danger` used as TEXT on `bg`**. The mockup uses them as **solid-fill backgrounds with `#FFFFFF` text** (the pill components). That second usage fails AA in dark mode for three of four:

| Pill | Dark fill | Text | Ratio | WCAG AA (4.5 normal / 3 large) |
|---|---|---|---|---|
| `pill-running` | `#7AA0C2` (info) | `#FFFFFF` | **2.75:1** | 🔴 fails both |
| `pill-done` | `#8FB97D` (success) | `#FFFFFF` | **2.23:1** | 🔴 fails both |
| `pill-failed` | `#D9706C` (danger) | `#FFFFFF` | **3.24:1** | 🔴 fails normal, passes large only |
| `pill-warning` | `#D4A852` (warning) | `#FFFFFF` | 2.61:1 | 🔴 fails both (not yet used but predictable) |

**Two valid fixes — pick one:**
- (A) On dark pills, **text colour = `#1A1715`** (the dark `bg`), not white. Ratios become 8.2 / 6.5 / 9.7+. Same fix for warning.
- (B) Darken the dark-mode semantic colours themselves (e.g. `--success` dark `#8FB97D` → `#4F7A3F` — the light value), then keep white text. Loses the "lifted in dark" character.

**Recommended: (A).** Preserves the warm-dusk palette and the "lifted, not desaturated" rule. The pill-color usage rule is now locked into `tokens.md §1` (see commit landing alongside this file).

Light mode also has two marginals (`warning` on `surfaceVariant` 4.28:1; `primary` on `surfaceVariant` 4.46:1) — same fix (A) applies: dark text on the fill, not the fill colour itself.

## Touch targets (the 🔴 you grepped — confirmed)

Every element below `min-height: 48px` that is `<button>` / `<a>` / interactive:

| Screen | Element | Current | Fix |
|---|---|---|---|
| Chat | `InputBar` mic icon | 40×40 (inline style overrides 48 base) | Drop the `style={{ width:40, height:40 }}` override. |
| Chat | `Thinking()` Cancel | 36 | `min-height: 48px;` |
| Chat | `PermissionCard` Grant access | 40 | `min-height: 48px;` |
| Chat | `SuggestionChips` `.chip` | 36 | `min-height: 48px;` (inner chip stays 36 via inner padding). |
| Modal | Toast `Undo` / `Dismiss` / `Edit` / `Try again` | 40 | `min-height: 48px;` |
| Audit | `fchip` filter chips | 36 | `min-height: 48px;` |
| Welcome / Permission / About | "Learn more" / "Open source on GitHub →" inline links rendered as `<button>` | 44 (exactly), no underline | Promote to `<a href>`, add `text-decoration: underline`, `min-height: 48px`. |
| All buttons | `.btn { height: 52; min-height: 48; }` | Fixed `height` clips at 200% font scale (WCAG 1.4.4). | Drop fixed `height`. `min-height: 52px;` only. |
| Appbar / statusbar / navpill | Fixed `height: 56 / 32 / 24` | Same clipping risk. | Use `min-height`. |

## Dialog / modal semantics

Every confirmation sheet (Chat confirmation, Confirmation modal screen, Audit "Clear history") has the same defects:

| Defect | Fix |
|---|---|
| No `role="dialog"` | Add `role="dialog"` |
| No `aria-modal="true"` | Add `aria-modal="true"` |
| No `aria-labelledby` pointing at the sheet title | Add it |
| Content behind not `inert` / `aria-hidden` | Mark `<ChatAppBar>` and `<InputBar>` `inert aria-hidden="true"` while open |
| No focus trap | Trap Tab inside the sheet |
| No Esc-to-close keyboard handler | Add it |
| "Don't ask again" rendered as `<span>`, not `<input type="checkbox">` | Real checkbox. |
| `RUNNING` state has no `aria-live` announce | `<span aria-live="polite" class="visually-hidden">Sending</span>` (or "Sent" on DONE). |
| `DONE`/`CANCELLED` terminal has no visible close button | Add `<button>Close</button>` and return focus to caller. |
| Destructive ("Clear history") missing `aria-describedby` pointing at "Cannot be undone" warning + initial focus should land on Cancel | Add both. |

## Live regions (state announcements)

| Screen | Defect | Fix |
|---|---|---|
| Loading model | Spinner + caption have no `role="status"`. SR users hear nothing during loading. | `<div role="status" aria-live="polite">Loading model — about 3 seconds.</div>` |
| Loading model — failed | "Model could not load." not announced. | `<div role="alert">…</div>` |
| Permission bounce — waiting | Dot pulse only; no live region. | `<div role="status" aria-live="polite">Checking permission…</div>` |
| Settings — search empty | "No match. Kindly try a shorter word." | Wrap in `role="status" aria-live="polite"`. |
| Chat — ErrorBubble | Color-only red border, no `role="alert"`, no icon. | Prepend `Ic name="error"` + add `role="alert"`. |
| Action card — SilentRibbon | Result message has no SR exposure. | `role="status"` for DONE, `role="alert"` for FAILED. |
| Action card — Toast | Auto-dismiss countdown is the only timing signal. WCAG 2.2.1 fail. | Expose remaining time `aria-live` ("4 seconds to undo") + pause-on-focus. |
| Modal — RUNNING | Cancel button disabled (no countdown). | Keep Cancel enabled or rename to "Force stop". Add `aria-busy="true"` on the dialog. |

## What passed
- `<html lang="en">` declared.
- Body-text contrast against backgrounds: mostly AAA-strong (>6:1) in both themes.
- `.btn` declares `min-height: 48` as floor (defeated by the `height: 52` override above — listed under touch targets).
- `.iconbtn` base = 48×48 (defeated by the inline 40×40 override in `InputBar` — same).
- No `<img>` tags — only inline SVGs (which need `aria-hidden` per above).
- No drag-only interactions — WCAG 2.5.7 N/A.
- Token hex palette: every value used in real UI matches the spec exactly. Zero off-palette colours in Mitra components.
- Font sizes used: 12/14/16/18/20/24/32 — exact 7-step scale.
- Inter font family declared throughout.
- No gradients / blur / glow outside the bundler-error overlay.
- All 13 V1 screens present.
- All 3 action-card modes present (Silent / Toast / Modal).
- All 5 action-card states present (CONFIRM / RUNNING / DONE / CANCELLED / FAILED) + recovery affordance (Try again).
- Voice taboo scan: zero hits for "guys / boss / dude / oops / sorry / namaste / theek hai" in user-visible strings.
